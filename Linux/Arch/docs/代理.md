# daed

## 安装

```bash
sudo pacman -S daed-avx2-bin # Optimized for x86-64 v3 / AVX2
sudo systemctl enable --now daed
# 浏览器访问 http://localhost:2023 , 配置并使用
# journalctl -xfu daed.service # 查日志
```

## 常用配置

---

**配置** (对应 dae 的 `global` 配置块)

1. 开启 "启用本地TCP快速重定向"
2. 填写 "LAN接口" 和 "WAN接口" (LAN接口可选加入docker虚拟网卡)
3. "TLS实现" 改为 `utls`, "uTLS模仿" 用 `edge_auto`

---

**DNS** (对应 dae 的 `dns` 配置块)

```lua
upstream {
  alidns: 'https://dns.alidns.com:443/dns-query'
  googledns: 'https://dns.google:443/dns-query'
}
routing {
  request {
    qname(geosite:category-ads-all) -> reject
    qtype(https) -> reject
    qname(geosite:cn) -> alidns
    fallback: googledns
  }
  response {
    upstream(googledns) -> accept
    ip(geoip:private) && !qname(geosite:cn) -> googledns
    fallback: accept
  }
}
```

---

**路由** (对应 dae 的 `routing` 配置块)

```lua
pname(NetworkManager, systemd-resolved, dnsmasq, sshd) -> must_direct
l4proto(udp) && dport(443) -> block
dip(224.0.0.0/3, 'ff00::/8') -> direct
dip(geoip:private) -> direct
domain(geosite:category-ads-all) -> block
domain(geosite:cn) -> direct
dip(geoip:cn) -> direct
dscp(0x04) -> direct
fallback: proxy
```

# FlClash

```bash
pacman -S flclash # 来自 ArchLinuxCN 源
```

配置:
1. `配置` -> `添加配置` -> 导入 URL 配置
2. `代理` -> `设置` -> 修改显示样式为紧凑标签页
3. `代理` -> 设置不同场景使用的节点. (不在乎隐私想省流量时 `漏网之鱼` 可选 `DIRECT`)
4. `工具` -> `资源` -> `同步` 更新数据
5. `工具` -> `应用程序` -> 开启 `退出时最小化`, `自启动`, `静默启动`, `自动运行`
6. `仪表盘` -> 开启 `虚拟网卡`, 点击右下角启动按钮打开

> 若无法上网, 尝试修改虚拟网卡栈模式为 `gvisor`

---

TUN 配置会导致 KDE 网络图标显示"连接受限", 但实际可上网  
检测命令: `nmcli networking connectivity check`, 正常时返回 full

原因:  
TUN + fake-ip 导致 NetworkManager 检测的域名 `ping.archlinux.org` 被解析到 fake IP 198.18.0.x  
NM 使用 `SO_BINDDEVICE` 绑定网卡发送检测请求, 绕过了 TUN 策略, 导致无法到达 fake IP

解决方法: 工具 -> 进阶配置 -> 脚本, 使用脚本:

```js
const main = (config) => {
  if (config.dns["fake-ip-filter"]) {
    config.dns["fake-ip-filter"].push("ping.archlinux.org");
  }
  return config;
};
```
