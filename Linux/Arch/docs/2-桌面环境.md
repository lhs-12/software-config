# 图形化相关包

图形化的构建分为以下几层(由低到高):

1. 物理硬件层: 显卡
2. 内核驱动层: 显卡的驱动程序
3. 用户态驱动层(API指令对接GPU指令的实现): Mesa(开源API实现库集合) / NVIDIA-Utils(英伟达独家)
4. API接口层: 图形(Vulkan/OpenGL), GPU计算(OpenCL), 编解码(VAAPI)
5. 应用层: 各种应用程序和框架(如GStreamer)

另外需要安装内核头文件让驱动正常编译工作.  
某些程序(Steam/Wine)需要额外安装32位的库(lib32-xxx).  
多显卡支持也需要额外的包.  
装完后建议重启一次.

```bash
# 1. 内核头文件: 确保驱动模块正确编译
# 需要对应内核版本：linux-headers, linux-zen-headers, linux-lts-headers
pacman -S --needed linux-headers

# 2. 内核驱动层

# 2.1 Nvidia
# 查看显卡family: https://nouveau.freedesktop.org/CodeNames.html
# 查驱动程序: https://wiki.archlinux.org/title/NVIDIA
# Turing(16系)及以后: 一律用开源内核模块系列(上游主推), 按内核选包:
#   nvidia-open(linux) / nvidia-open-lts(linux-lts) / nvidia-open-dkms(任意内核)
# 建议用dkms版: 任意内核通用, 且内核变更/更换内核会自动重新编译驱动
pacman -S --needed nvidia-open-dkms

# 2.2 AMD
# https://wiki.archlinux.org/title/AMDGPU
# 驱动(linux-firmware-amdgpu)已包含于linux-firmware, 不用特意装

# 2.3 Intel
# https://wiki.archlinux.org/title/Intel_graphics
# 驱动(linux-firmware-intel)已包含于linux-firmware, 不用特意装

# 3. 用户态驱动层 (API 调用 -> GPU 指令)

# 3.1 AMD (使用mesa)
pacman -S mesa lib32-mesa
# 3.2 Intel (同样使用mesa)
# pacman -S mesa lib32-mesa
# Mesa 集合包含: OpenGL实现 / Vulkan驱动 / VAAPI实现 / OpenCL开源实现

# 3.3 NVIDIA
# NVIDIA 不用 Mesa, 用独家实现, 包含的实现: OpenGL, Vulkan, 基础 GPU 支持库
pacman -S nvidia-utils lib32-nvidia-utils
# nvidia-utils 通过 modprobe(内核模块加载工具) 配置禁用了 nouveau (内核自带的N卡开源社区驱动, 与官方驱动互斥), 重启后生效
sudo systemctl enable --now nvidia-powerd.service # 启用动态功耗调节(nvidia-utils附带服务)

# 4. API 接口层

# 4.1 图形 API (OpenGL / Vulkan)
# 4.1.1 AMD
# xf86-video-amdgpu 是 X11 环境下的 2D 驱动, vulkan-headers非必需
pacman -S vulkan-radeon lib32-vulkan-radeon vulkan-headers xf86-video-amdgpu
# 4.1.2 Intel
# pacman -S vulkan-intel lib32-vulkan-intel vulkan-headers
# 4.1.3 NVIDIA
# Vulkan 驱动已由 nvidia-utils 提供
# pacman -S vulkan-icd-loader lib32-vulkan-icd-loader vulkan-headers

# 4.2 GPU 计算 API (OpenCL)
# https://wiki.archlinux.org/title/General-purpose_computing_on_graphics_processing_units#Runtime
# 4.2.1 AMD (开源通用版, 非最佳性能版)
pacman -S opencl-mesa lib32-opencl-mesa opencl-icd-loader lib32-opencl-icd-loader
# 4.2.2 Intel (同AMD)
# 4.2.3 NVIDIA
# pacman -S opencl-nvidia lib32-opencl-nvidia opencl-icd-loader lib32-opencl-icd-loader

# 4.3 视频编解码 API (VAAPI)
# https://wiki.archlinux.org/title/Hardware_video_acceleration

# 4.3.1 AMD
# 已由 Mesa 提供, 无需额外安装

# 4.3.2 Intel
# pacman -S intel-media-driver # 底层 VAAPI 驱动(Broadwell后通用)
# 其他需要的去看 wiki 选, 比如 QSV硬转码API包(VAAPI 上层)

# 4.3.3 NVIDIA
# 由nvidia-utils和libva-nvidia-driver提供
# 可考虑替换为nvidia-vaapi-driver, 据wiki说功耗更低(archlinuxcn有)
# pacman -S libva-nvidia-driver

# 4.3.4 可选装验证工具(重启后验证)
pacman -S vulkan-tools mesa-utils clinfo libva-utils
vulkaninfo  # Vulkan 验证
glxinfo -B  # OpenGL 验证, 看 renderer 字段
clinfo      # OpenCL 验证
vainfo      # VAAPI 验证
# 多显卡要改环境变量指定 VAAPI 驱动名: nvidia(N卡), iHD(Intel核显), radeonsi(A卡)
# LIBVA_DRIVER_NAME=xxx vainfo # xxx改成驱动名

# 5. 应用层
pacman -S gst-plugin-va # GStreamer的VAAPI插件, 一些桌面软件用到
pacman -S lact # GPU控制面板, 可做频率/电压offset

# 6. 多显卡联动(混合图形, 常见为 核显 + N卡独显)
# 参考: https://wiki.archlinuxcn.org/wiki/混合图形技术
# 参考: https://wiki.archlinuxcn.org/wiki/PRIME
# 参考: https://wiki.archlinuxcn.org/wiki/NVIDIA_Optimus

# 6.1 基础配置
# 通用: 桌面选卡服务(厂商无关, N/A/I卡通用)
sudo pacman -S --needed switcheroo-control
sudo systemctl enable --now switcheroo-control

# 独显为N卡: PRIME 渲染卸载(N卡官方方案)
# PRIME: 内核多显卡协作机制; 渲染卸载(render offload): 按程序粒度把渲染任务转交给独显
# 效果: 日常核显渲染, 按需独显出力 ; nvidia-prime 提供 prime-run
sudo pacman -S --needed nvidia-prime

# 独显为A/I卡: DRI_PRIME 选卡
# DRI_PRIME 是 Mesa 内置机制, OpenGL 开箱即用, Vulkan 需补装 vk-device-select 层
sudo pacman -S --needed vulkan-mesa-layers lib32-vulkan-mesa-layers

# 6.2 用独显运行程序
prime-run 程序    # N卡, 等价于 __NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia
DRI_PRIME=1 程序  # AMD/Intel 独显(开源驱动), Vulkan 程序用 DRI_PRIME=1!
# KDE: 应用右键 -> 编辑应用程序 -> 高级 -> 用独显运行 (依赖 switcheroo-control)
# Wine/DXVK 游戏选卡: DXVK_FILTER_DEVICE_NAME=显卡名 程序

# 6.3 验证
lsmod | grep nvidia                         # 应列出 nvidia 系列模块
lsmod | grep nouveau                        # 应无输出(nouveau 已被屏蔽)
nvidia-smi                                  # GPU 和驱动状态
prime-run glxinfo | grep "OpenGL renderer"  # 应显示 N 卡型号
vulkaninfo --list-devices                   # 列出两张卡的 Vulkan 设备
LIBVA_DRIVER_NAME=nvidia vainfo             # 独显 VAAPI(nvidia / iHD / radeonsi)

# 6.4 可选: N卡模块提前加载进 initramfs, 出现显示管理器先于驱动启动(黑屏/加载慢)时配置
# 注意: 会导致休眠失效(显存保存机制), 有休眠需求不要加
# echo 'MODULES=(nvidia nvidia_modeset nvidia_uvm nvidia_drm)' | sudo tee /etc/mkinitcpio.conf.d/10-nvidia.conf
# sudo mkinitcpio -P

# 6.5 独显闲置断电(RTD3 运行时电源管理)
# 现代卡默认启用; 异常时按 wiki 手动配 udev 规则+模块参数
# 参考: https://wiki.archlinux.org/title/PRIME#PCI-Express_Runtime_D3_(RTD3)_Power_Management
# 检查(可选): 独显 PCI 地址换自己的(lspci | grep -i nvidia)
# cat /sys/bus/pci/devices/0000:01:00.0/power/runtime_status # suspended = 已断电
# RTD3 生效后部分程序首次打开慢约1秒(独显唤醒), 正常现象

# 6.6 故障排查
# GTK4 程序花屏/闪烁: 对问题应用单独设置 GSK_RENDERER=gl 或 cairo
# 双系统里 Windows/厂商工具开 Eco 模式会屏蔽独显, 导致 Linux 检测不到
# 驱动装完黑屏: 进 GRUB 选旧内核或急救 shell 进系统, 删除 6.4 的 drop-in 后重建 initramfs, 回退 nouveau 亮机
# DKMS 编译失败: 检查 headers 与内核版本一致 (pacman -Q linux linux-headers)
# 查谁占用着独显: lsof +c0 /dev/nvidia*

# 6.7 显卡模式切换(整体切换, 区别于 6.2 的按程序切换)
# Wayland 下切换不完善: 混合模式与核显模式可互切, 独显直连需进 BIOS 调整
# KDE 可用 envycontrol 切换模式, 配套挂件 Optimus GPU Switcher 可在任务栏一键切
# 注: envycontrol 上游已停更, 可能有问题
```

# 修改键盘映射

```bash
# xremap 方案
# 以下步骤适用于KDE, 其他情况参考官方文档
paru -S xremap-kde-bin
# 1. xremap 默认需要 sudo 权限, 通过下面步骤让其免去sudo
# 1.1. 启用uinput模块
lsmod | grep uinput # 检查模块是否已加载
echo uinput | sudo tee /etc/modules-load.d/uinput.conf # 如果为空, 创建模块加载文件(需重启生效)
# 1.2. 添加 udev 权限规则(让普通用户也能访问 /dev/uinput)
echo 'KERNEL=="uinput", GROUP="input", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/99-input.rules
# 1.3. 把当前用户加入 input 组
sudo gpasswd -a $USER input

# 2. 开机自启 (无需执行, 配置文件通过dotfiles管理)
# 2.1. 可通过 systemctl 自启动
# 编辑 ~/.config/systemd/user/xremap.service
# systemctl --user start xremap
# systemctl --user enable xremap
# 2.2. 官方更推荐用 autostart desktop 确保正常启动
# systemd --user 服务可能太早启动, 导致 xremap 无法检测到窗口管理器
# 编辑 ~/.config/autostart/xremap.desktop
```

输入法使用异常的解决办法

```bash
# 原因: Wayland 与 X11 在输入法协议和应用适配层面的实现差异
# 可能导致: 输入漏字; 删不掉输入框最后一个字符; 输入卡顿延迟; 删除输入框字符时误删右侧已输入内容; 输入法不可用
# 解决方式: 增加运行参数. 但要避免全局设置单数输入法模块, 仅对存在问题的应用单独添加运行参数.
# 说明:
# 基于Wayland运行的图形化环境(KDE, HyprLand, Niri, Sway...),
# 若全局设置单数 GTK_IM_MODULE/QT_IM_MODULE, 原生 Wayland 应用被迫改用 im module,
# 可能导致输入法候选框闪烁和位置错误等问题, 但若不设置, 又会在 XWayland 或 Electron 应用中出现输入异常.
# 因此全局只设置安全的环境变量(可dotfiles管理), 其余设置仅在存在问题的应用上单独指定.
# 遇到问题时建议查阅最新文档: https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland
# 安全设置包括:
# XMODIFIERS=@im=fcitx               # XIM 协议, 兜底 XWayland 应用
# QT_IM_MODULES="wayland;fcitx;ibus" # QT 复数形式, 按序 fallback, 支持 Qt 6.7+, Qt5 及以下不识别该变量
#
# 1. 修改全局基本语言参数(dotfiles管理)
# 修改locale的 LANG 为英文, LC_MESSAGES 为中文: 保持中文界面同时, 避免中文locale导致的输入法异常
# 修改 ~/.config/environment.d/ 下的变量和 KDE Plasma 语言配置(~/.config/plasma-localerc)
# 写入这两个环境变量
# LANG=en_US.UTF-8
# LC_MESSAGES=zh_CN.UTF-8
# 若使用其他Wayland合成器(比如Niri), 需要在其窗口管理器配置中设置这两个参数
#
# 2. 针对存在输入异常的应用单独设置启动参数
# 通用方法: 复制 /usr/share/applications/<app>.desktop 到 ~/.local/share/applications/, 修改其中 Exec= 行
# 环境变量用 env 前缀传入(Exec=env GTK_IM_MODULE=fcitx <command>), 命令行参数直接追加在命令后
# 2.1 GTK 应用: 启动时加环境变量 GTK_IM_MODULE=fcitx
# 2.2 Qt 应用: 根据桌面环境和 Qt 版本选择
#      KDE 环境: 通常不需要设置 QT_IM_MODULE( KWin 支持 text-input-v2 )
#      非 KDE 环境: QT_IM_MODULE=fcitx
#      Qt 6.7+: 已全局设置 QT_IM_MODULES 配置
# 2.3 专有 Qt 应用 (WPS, Anki, DaVinci Resolve 等):
#      尝试 QT_IM_MODULE=fcitx (如果捆绑了 fcitx im module)
#      尝试 QT_IM_MODULE=ibus (如果捆绑了 ibus im module)
#      兜底方案: QT_QPA_PLATFORM=xcb QT_IM_MODULE=ibus (强制 X11/XWayland)
# 2.4 Chromium 和 Electron 应用:
#      先尝试: --ozone-platform=wayland
#      不行再试: --enable-features=UseOzonePlatform --ozone-platform=wayland --enable-wayland-ime
#      若还有问题, 尝试修改 --wayland-text-input-version=3或1
# 2.5 SDL2 应用: SDL_IM_MODULE=fcitx
# 2.6 有些软件 Wayland 支持不好, 尝试换到 XWayland: --ozone-platform=x11
# 2.7 有些软件locale的LC_CTYPE变量为英文时可能无法输入中文, 此时单独设置中文LC_CTYPE变量
```

**Edge 浏览器**  
`paru -S microsoft-edge-stable-bin`

问题: Edge 浏览器的鼠标手势功能不正常, 需要双击才能划手势.  
参考 [Github discussions](https://github.com/orgs/linuxmint/discussions/1056)  
用 Tampermonkey 脚本解决.

1. Edge 进入扩展页面, 打开 "开发人员模式"
2. 右键 Tampermonkey, 保存以下内容为用户脚本

```js
// ==UserScript==
// @name         双击右键菜单
// @namespace    http://tampermonkey.net/
// @version      2025-07-05
// @description  只有在双击右键时才会显示浏览器原生右键菜单
// @author       xiaochen0517
// @match        *://*/*
// @icon         https://www.google.com/s2/favicons?sz=64&domain=greasyfork.org
// @grant        none
// ==/UserScript==
(function () {
  "use strict";
  // 用于记录右键点击的时间戳
  let lastRightClick = 0;
  const doubleClickSpeed = 300; // 双击判定的时间间隔（毫秒）

  // 监听右键点击事件
  document.addEventListener(
    "contextmenu",
    function (event) {
      const currentTime = new Date().getTime();
      const timeDiff = currentTime - lastRightClick;
      // 如果时间间隔小于设定值，认为是双击右键
      if (timeDiff < doubleClickSpeed) {
        // 双击右键，允许显示原生菜单
        lastRightClick = 0; // 重置时间戳
        return true;
      } else {
        // 单击右键，阻止显示原生菜单
        event.preventDefault();
        lastRightClick = currentTime;
        return false;
      }
    },
    true
  );
})();
```
